1. Executive Summary
TPT Lexicon is a suite of no_std-compatible Rust crates that replaces the traditional text-to-token preprocessing pipeline with a neuro-symbolic, zero-copy, and formally-verifiable architecture.
It targets the three compounding bottlenecks of modern LLM inference: sequential tokenization latency, semantic context waste, and structural hallucination. Crucially, it includes a Translation Bridge that allows this advanced pipeline to accelerate existing legacy LLMs without requiring them to be retrained from scratch.
2. Problem Statement
The Tokenization Bottleneck: Standard BPE is sequential and CPU-bound, dominating Time-To-First-Token (TTFT) latency for long contexts.
The Context Tax: English-optimized tokenizers waste massive amounts of context on non-English text, code syntax, and structured data.
The Legacy Weight Problem: State-of-the-art compression and symbolic IRs are useless if existing, pre-trained LLMs cannot consume them natively.
The Structural Hallucination Problem: LLMs operating on flat token sequences cannot guarantee syntactic correctness, requiring expensive downstream re-parsing and validation.
3. Purpose
TPT Lexicon exists to provide a foundational, reusable, and interoperable preprocessing layer for any AI inference engine, local runtime, or cognitive system. It treats text not as a string to be chunked, but as a structured signal to be parsed, compressed into a Symbolic IR, and translated into the optimal representation for the target model.

6. Crate Breakdown
6.1 tpt-lexicon-core
Role: Foundational tokenizer engine.
Properties: no_std, zero-copy UTF-8 slicing.
Innovation: Parallel prefix-sum BPE and SRAM-native vocabulary mapping. Executes entirely in GPU shared memory or CPU L1/L2 cache to eliminate memory bandwidth bottlenecks.
6.2 tpt-lexicon-ingest
Role: Streaming, syntax-aware parser.
Properties: Yields semantic chunks without allocating full strings in memory.
Targets: Code (via Tree-sitter interop), Markdown, JSON, and natural language paragraph boundaries.
6.3 tpt-lexicon-ir
Role: Symbolic Intermediate Representation.
Innovation: Fractal Compression. Identifies repeating structural sub-graphs and replaces them with recursive grammar rules, achieving logarithmic context scaling for boilerplate and repetitive structures.
Properties: Serializable, diffable, verifiable.
6.4 tpt-lexicon-verify
Role: Formal verification of IR edits and outputs.
Properties: Rejects outputs violating structural invariants (e.g., mismatched braces, invalid type references, broken borrow rules) before they are translated back to text.
6.5 tpt-lexicon-translate (The Bridge)
Role: Interoperability and Just-In-Time (JIT) expansion.
Function 1 (Legacy Bridge): Takes the compressed tpt-lexicon-ir and unrolls it into the exact sequence of discrete token IDs expected by a standard, pre-trained LLM (e.g., Llama, Mistral).
Function 2 (Cross-IR): Translates the internal IR into external standard formats (Tree-sitter AST, LSP, LLVM IR) for external tooling.
Function 3 (Tokenizer Agnostic): Loads any existing tokenizer.json and maps it into the zero-copy tpt-lexicon-core structures on the fly.
6.6 tpt-lexicon-gpu
Role: Hardware acceleration.
Backends: wgpu (portable) and optional raw CUDA/Metal.
Feature-gated: Entirely optional; core stack runs on CPU.
7. Phased Milestones
Phase 1 — Foundation & Core (Weeks 1–4)
Workspace scaffolding, CI, no_std baseline.
tpt-lexicon-core: parallel BPE on CPU; zero-copy byte slicing.
Benchmark harness vs. Hugging Face tokenizers reference.
Phase 2 — IR & Fractal Compression (Weeks 5–10)
tpt-lexicon-ingest: streaming parser for Rust + TypeScript.
tpt-lexicon-ir: initial typed AST schema.
Implement fractal/recursive compression rules for boilerplate detection.
Phase 3 — The Translation Bridge (Weeks 11–14)
tpt-lexicon-translate: JIT unrolling of IR into standard BPE token IDs.
Load and map external HuggingFace vocabularies into tpt-lexicon-core.
Integration test: Pass compressed IR through the bridge into a standard GGUF model.
Phase 4 — Verification & GPU (Weeks 15–20)
tpt-lexicon-verify: formal proof contracts for IR edits.
tpt-lexicon-gpu: SRAM-native parallel tokenizer via wgpu.
End-to-end demo: 100K-line codebase → compressed IR → verified → translated to legacy tokens → inferred.
8. Risks & Tradeoffs
Risk
Mitigation
Translation overhead kills the speedup
The tpt-lexicon-translate JIT unrolling must be executed on the GPU in parallel with the first layers of the LLM, hiding the latency.
Fractal IR is too rigid for open-ended text
Fractal compression is applied only to highly structured data (code, JSON, logs). Natural language uses standard semantic pooling.
no_std parser coverage gaps
Interop with tree-sitter via C-bindings where no_std pure Rust is impractical.
